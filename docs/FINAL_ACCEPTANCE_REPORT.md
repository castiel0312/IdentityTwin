# IdentityTwin Live End-to-End Acceptance Report

**Run date:** 2026-11-04 (UTC)  
**Environment:** the running IdentityTwin development Docker stack; development auth personas; mock provider; synthetic `.example.test` recipients. No production policy or risk thresholds were changed. No real-money payout was attempted.

## Result summary

- **PASS:** live frontend and API flows for NORMAL, RESTRICTED, DECOY, and ISOLATED routing; step-up; mock/honey provider isolation; behavioral drift; cross-merchant vaccination; analyst investigation; evidence seals; idempotency; and automatic containment SSE updates after the fix.
- **PASS:** durable authenticated tenant-scoped outbox events, ordered replay after an API restart, and live payout/risk event delivery. A live browser confirmed automatic payout-ledger and overview-metric refresh after mock payouts.
- **FAIL (fixed and reverified):** the overview's analytics end-time was frozen at page mount, excluding later payouts on SSE-triggered refetches. The query now creates a fresh range per fetch; the open dashboard's payout count advanced from 27 to 28 without reload.
- **BLOCKED:** a PayPal Sandbox payout, because no controlled sandbox recipient account was configured. PayPal Sandbox OAuth and a read-only identity request did succeed.
- **BLOCKED:** LLM-generated investigation narrative; this stack had LLM use disabled. The deterministic, redacted investigation workflow did succeed.
- The product is **not claimed to be fully real-time**: live frontend updates for session detail, incident, vaccination, evidence, and analyst workflow pages were not independently observed in this run.

Historical reports already in the worktree were not treated as evidence for this run. The acceptance observations below came from the live stack or from the explicitly identified automated tests.

The synchronous payout/risk acceptance rows below were run before the durable domain-event extension. Their “no SSE event expected” notes describe those original observations, not the current implementation's advertised event coverage.

## Operational notes

The SSE precision fix preserves event IDs as strings and uses `BigInt` only for ordering. The durable outbox uses per-merchant event IDs and retains events for 30 days. The browser reconnected after an API restart and replayed persisted events from a deliberately older cursor. A live query refresh initially exposed a frozen `end` timestamp in the overview range; moving range calculation into each query execution fixed it. The final deployed console and API were healthy.

The backend stack remained in development mode with the mock provider. No credentials, OTP values, access tokens, or real recipient data are included in this report.
